# Архитектура egogo

## Два приложения

### Client (Wails)

Desktop-приложение. Работает автономно — все данные профиля «My» хранятся локально.

- UI: React + TypeScript
- Backend: Go (Wails bindings)
- Локальное хранилище: `~/.egogo/`

### Server (Go web)

Self-hosted сервер для организаций.

- REST API + web-интерфейс администрирования
- Управление пользователями, ролями, проектами
- Безопасное хранилище проектов (зашифрованные файлы / SQLite + blob storage) (путь до хранилища по умолчанию: `~/.egogo-server/`)
- Опциональная интеграция с Git

## Профили

| Тип      | Хранение               | Сервер      |
|----------|------------------------|-------------|
| `local`  | Только на машине       | Нет         |
| `remote` | На self-hosted сервере | Да          |
| `git`    | Git-репозиторий        | Опционально |

Пользователь может переключаться между профилями через нижнюю панель.

## Проекты и окружения

```
Профиль
├── Проект A
│   ├── Папка / Запросы
│   └── ...
├── Проект B
│   └── ...
└── Environments (глобальные для профиля)
    ├── dev
    ├── staging
    └── production
```

## Синхронизация

1. **Server sync** — клиент ↔ self-hosted API
2. **Git sync** — push/pull JSON/YAML файлов проекта в репозиторий

Git-режим решает проблему «устаревших коллекций в Confluence»: источник правды — репозиторий.

## Безопасность (server)

- Пароли: bcrypt
- Сессии: короткоживущие JWT + refresh token
- Invite-ссылки: одноразовые, TTL 24–72 ч (см. AUTH.md)
- Данные проектов: шифрование at-rest (AES-256-GCM)
- HTTPS обязателен в production
